---
title: Shared workspace
description: Durable state, background collectors, and native Mac and Android clients.
---

A workspace owns durable app state. Each device owns its navigation, open views,
keyboard state, and unsaved editor drafts. Terminals, files, Git, ports, and notebook
servers remain on their machine brokers and do not depend on the workspace host.

## Choosing a workspace

The existing local sync host enrolls through a loopback-only request. Other clients
select its advertised workspace identity. Android can select the sole enrolled host
automatically; multiple enrolled hosts require an explicit choice in Workspace.
The host is never chosen by operating system, hostname, or discovery order.

The Mac settings panel and Android Workspace screen show the selected host, pending
changes, errors, and concurrent edits requiring review. Switching workspaces selects
separate document stores, replica caches, and artifact libraries. Pending writes stay
with their original workspace.

## Ownership

| State | Owner |
| --- | --- |
| Notes, Todos, Workflows, Planner | Selected workspace host, using the document three-way merge API |
| Backlog and activity acknowledgments | Versioned workspace records |
| Usage settings and warning dismissals | Versioned workspace records |
| Usage readings, Command Center summaries, journal manifests, Wrapped | Background collectors publishing workspace records |
| Dashboard and notebook definitions | Workspace catalogs; each client resolves its own connection |
| Saved artifacts and archived source | Workspace metadata plus immutable content-addressed blobs |
| Sessions, hidden flags, files, Git, ports, notebook runtimes | Owning machine broker |
| Editor drafts | Durable local files, keyed by broker identity and path |

## Synchronization contract

`/whoami` advertises stable broker/workspace identities and protocol capabilities.
Session records include a lifetime identity and broker-issued activity revision.
Renaming a session retains its identity; recreating one with the same name does not.
Read acknowledgments refer to an activity revision, so new activity becomes unread.

Broker storage is namespaced by installation identity and session-provider socket.
Embedded network runtimes supply their durable installation identity (tsnet uses
its stable node ID), not their hostname, address, or a container's cloned machine
ID. Local brokers retain their OS-derived roots. `UT_MACHINE_ID` overrides either
source when an installation identity is managed explicitly. Runtime identity state
must be preserved with the installation; re-registering a new node is a new identity.

When upgrading a network broker with an existing OS-derived store, verify which
installation owns that store and map the new root to the existing directory before
restarting. The broker reports both paths and refuses to guess ownership or silently
replace that store. A distinct installation sharing the cloned OS identity requires
an explicitly created separate root. Existing records, receipts, broker IDs, and
session lifetimes remain in the original owner's store.

The versioned API includes:

- `GET /workspace/info`, `/workspace/snapshot`, and `/workspace/record`.
- `GET /workspace/changes?after=CURSOR&limit=500&wait=25` for resumable updates.
- `POST /workspace/mutate` with a mutation ID and expected base revision.
- `POST /workspace/lease` for fenced collector ownership.
- `PUT`, `HEAD`, and `GET /workspace/blobs/SHA256` for immutable files.

The broker commits records, mutation receipts, and change events in one bbolt
transaction. Lost acknowledgments are retried with the same mutation ID. Device
timestamps do not determine the winning edit. A receipt does not advance a client's
change cursor past unseen events. An expired cursor causes a fresh snapshot.

Both native replicas retain cached content after failure, persist pending changes
before displaying them, reject older revisions, and preserve conflicting copies.
Independent object-field changes merge; competing changes require an explicit
choice. Tombstones prevent stale clients from recreating deleted records.

## Collectors and account controls

The Mac installs a per-user launch agent named `dev.universaltmux.workspace` that
runs the signed app executable with `--workspace-worker`. Closing the app's windows
does not stop collection. Expiring leases and fencing tokens prevent a replaced
worker from publishing a delayed result. The UI requests refresh through the service.

Connections on both clients use `/workspace/service/usage`. This is a bounded,
memory-only request/reply channel, not a durable mutation queue. Only the local
lease-owning collector can retrieve or answer requests. Credential inputs and login
codes never enter replica caches, mutation receipts, change logs, or backups.
Account credentials remain in the collecting host's existing private stores.
An unacknowledged account action is not automatically retried; reload Connections
to check its result. Normalized readings continue to use the durable workspace API.

Shared-session status changes remain pending until the corrected status is published.
The collector retains their feedback for its next model response across restarts and
removes it only after that response is published. A correction is not a permanent
status lock.

Sessions without shared identities use their broker's existing `/ccoverride` relay.
Both clients show the pending label, retain its session lifetime, and report rejected
saves. The collector publishes the relay receipt as `appliedOverrideTS` before clearing
the relay; clients can acknowledge delivery even if the model has already reconsidered
the label. Older publications can still acknowledge a fresh matching label. Native
status publications are serialized and coalesced per broker. Route-local session
witnesses are never written as shared session identities.

Journal ingestion and Wrapped computation run as independent, single-flight jobs.
All Wrapped periods share one archive snapshot, so a slow computation does not stop
journal publication.

## Files and artifacts

Text editors use `/fs/document` with content revisions and conditional saves.
A changed remote file is returned for review instead of silently overwritten.
Drafts retain their exact base and survive navigation or a client restart.

Artifact metadata synchronizes separately from files. Blob transfers are hash
verified and limited to 128 MiB per file. Android stages outgoing transfers durably;
Mac retains local originals until synchronization succeeds. Render exports retain
both a PDF and the authored-source archive.

Dashboard catalogs contain portable website addresses or broker/port/path locators,
never client-local forwarded URLs, cookies, or authentication parameters. Notebook
tokens remain in each device's live connection rather than the shared definition.

## Migration and recovery

Existing document files and catalog preferences are retained before migration.
Legacy session marks migrate once by lifetime, rather than following a reused name.
The artifact library is partitioned by workspace while preserving its original files.

The broker creates one atomic database backup per UTC day and retains seven daily
backups beside its workspace database. Immutable blobs are retained separately.
Restoring requires stopping the owning broker and restoring a matching database
and blob store. Client caches and pending changes are separate recovery inputs;
discarding a cache also discards its uncommitted changes.

Shared Swift/Kotlin fixtures and broker tests cover lost acknowledgments, offline
edits, reordering, conflict queues, workspace switching, tombstones, and session
lifetime changes across tmux and ConPTY identity formats. The separate Android
`.qa` application exercises production screens against a loopback fixture server,
without connecting to accounts or the tailnet.
