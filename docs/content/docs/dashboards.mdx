A lot of what agents produce lives behind a web UI on the machine that ran them — a training
dashboard, a TensorBoard, a Jupyter server. Reaching those normally means an `ssh -L`, a forwarded
port, and a browser tab. Argus folds that into the app: a built-in, tabbed browser that reaches any
host's web service over the same tailnet, plus first-class Jupyter notebooks that run on the host.

## Dashboards

The **Dashboards** window is a small web browser with durable tabs, back/forward/reload, an address
bar, `⌘F` find-in-page, and independent `⌘+` / `⌘−` / `⌘0` zoom. Open a tab against a host
and Argus sets up the [port-forward](/docs/ports) for you, so a server bound to
`localhost:6006` on a cluster node is just *there*, no manual tunnel.

The empty window is a **service catalog** across your machines. Argus inspects listening ports and
performs an actual HTTP probe before showing a service card; it does not guess from a process or
port name. Desktop-app noise is hidden by default and available behind **Show all**.

For dashboards that should stay current without interaction, each tab can auto-refresh every 5,
15, 30, or 60 seconds. Open tabs and their host/port identity persist across app launches.

## Agent-controlled browser

When Argus is open on the Mac, an agent on **any** `ut` machine can drive the same WebKit browser
through `ut browser`. New agent tabs are hidden by default; `show` promotes the exact live tab into
Dashboards in the background without reloading it, taking focus, or losing its cookies, JavaScript
state, or scroll position.

```bash
ut browser status
ut browser open https://example.com
ut browser tabs
ut browser downloads <tab-id>
ut browser snapshot <tab-id>
ut browser screenshot <tab-id> -o page.png
ut browser click <tab-id> 420 260
ut browser type <tab-id> --ref e7 "search text"
ut browser upload <tab-id> --ref e12 /absolute/path/to/results.pdf
ut browser scroll <tab-id> 0 700
ut browser show <tab-id>
```

Screenshots are first-class observations: an explicit `screenshot` writes the PNG where requested,
and every click, type, or scroll writes its resulting viewport PNG to a temporary observation path
on the agent's machine. `snapshot` returns readable page text plus interactive elements and stable
references such as `e7`; coordinate actions use top-left screenshot coordinates.

Page-requested windows become real sibling tabs, preserving opener state, POST targets, cookies,
and blank-first document flows instead of replacing the current page. Native WebKit downloads keep
that same authenticated request and save collision-safe filenames into the Argus Mac's Downloads
folder. Click output reports newly opened tab IDs and download destinations; `downloads <tab-id>`
shows whether each transfer is downloading, finished, or failed.

`upload` reads the file on the machine where the command runs—even when that is Babel—and attaches
it directly to the page's `<input type="file">`. It does not open a native file picker or activate
Argus. Hidden file inputs appear in `snapshot`; target one by ref/coordinates, or omit the target
when the page contains exactly one file input. The aggregate upload limit is 32 MiB per command.

The browser process, WebKit profile, cookies, and network connection all remain on the **Mac running
Argus**. A command issued on Babel is relayed Babel broker → Mac broker → Argus, so opening Gmail
uses the Mac's network and login session—not Babel's. `ut browser status` states both the browser
host and network origin explicitly.

## JupyterLab

**New → JupyterLab** asks for a machine and a folder, and opens the host's **full JupyterLab rooted
at that folder** in the main pane — file browser, launcher, and all. Create or open notebooks from
the Lab itself. The key point: **the kernel runs on the host** — the GPU node, with its environment
and data — while you edit and run cells from your Mac. No SSH, no copying notebooks around, no local
kernel.

The pane is durable in both directions: switching to a terminal and back does **not** reload the Lab
(your unsaved cell edits stay put), and open Labs are remembered across app restarts — the server
keeps running on the host, and reopening reconnects to it. The broker also launches Jupyter with its
network phone-homes disabled, so a cold start on an egress-restricted cluster node takes seconds,
not minutes, and autosave is tightened to 30s so an app quit loses at most that much.

<Callout type="info">
Both ride the existing per-host broker and the port-forward hub — there is no extra service to deploy.
A notebook's kernel and a dashboard's server live on the machine that owns the work; Argus just gives
you a window onto them.
</Callout>
